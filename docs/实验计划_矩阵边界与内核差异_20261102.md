## 目标与验收

目标仍为任意尺寸的 FP16 GEMM 时延误差不超过15%。有限验证通过仅证明已测范围，不宣称任意尺寸均已保证。
本轮不修改原有“规则/非规则”分组，不删除失败样本，不从验证 GEMM 时延拟合形状修正系数。
报告每项的有符号相对误差、绝对相对误差、最大误差、通过率、两轮测量稳定性，并单独报告预先声明的未见尺寸。

## 第一阶段：定位机制

1. 重测10个历史非规则案例和7个规则/长K控制案例，判断环境变化与复现稳定性。
2. 固定两个维度，只改变 M、N 或 K；重点覆盖对齐边界±1及不同K余数。
3. 保持逻辑矩阵尺寸不变，分别将A、B、C或全部矩阵的物理行跨度补齐到16元素。此组为因果干预，不替代原连续布局基准。
4. 用独立 profiler 批次只记录实际内核名称、数量及其可解析参数；Profiler时间不进入准确率比较。
5. 另保留12个预先声明的新尺寸，不用于参数拟合。当前阶段先不采集其时延，待改进机制确定后测量。

计时与历史一致：单卡FP16、`torch.mm(A,B,out=C)`，30次预热；每个Graph含64或256次同地址GEMM，预热6次后测两轮，每轮25次GPU Event计时除以Graph中的GEMM数量。结果是同地址Graph稳态下的每GEMM平均服务时间，不代表冷缓存或CPU逐次发射场景。

## 当前证据与待验证假说

- 历史10个非规则矩阵均调用名称带MMAC的内核，不能直接解释为SIMT回退。
- 实际库采用的宏块、K深度、向量读宽度随尺寸变化；模型目前自主搜索理想映射，两者可能预测的是不同执行计划。
- 历史 `512×768×16384` 存在GSU8及额外PostGSU归约内核，当前常驻C、不拆K方案没有建模该路径。
- 尾块的指令补齐仅覆盖矩阵单元工作量，不必然覆盖地址判定、边界装载、尾K循环和吞吐下降。
- 当前资源模型只检查CU聚合寄存器预算；实际每线程寄存器分配及驻留工作组可能改变可隐藏的访存延迟。

这些均为调查方向；不得在对照实验前直接归因或添加经验倍数。

## 改进与回归路线

先建立“请求尺寸与布局 → 实际执行计划 → 分阶段资源服务 → 总时延”的证据链。
将自主搜索最优映射与预测指定运行库执行的模式区分；实际内核信息用于诊断时必须注明，不能伪称仅凭M/N/K就已预测其选择。
根据实验决定是否补充：行跨度与访问对齐、边界/尾循环、真实宏块与工作组数量、Split-K与额外归约、工作组驻留和内存延迟隐藏。
所有新参数须来自明确的硬件资料或独立微基准；新机制分别做单变量消融，再回归历史60个验证样本与新尺寸。

## 本机已完成的第一项消融

新增 `superpod_compute/kernel_plan.py`，解析显式提供的实际内核宏块，正确处理行主序 `torch.mm` 转换到BLAS后M/N轴的交换。它不预测库的内核选择，也不把静态向量宽度当作所有动态访问的真实宽度。

`evaluate_macrotiling_ablation()`固定实际宏块和DepthU，仍使用V3.2服务公式；缓冲和CU组形状继续搜索。这只是“更换宏块”的单变量消融，不是完整的库内核模型。Split-K案例明确拒绝，防止漏算归约后得到貌似有效的时延。

在本机已有的60组历史验证数据上：59组可执行本次消融，1组Split-K暂不支持；原模型在相同59组上通过41组，本次通过42组。非规则10组的平均绝对相对误差从61.78%降到53.79%，仍为0/10通过。部分规则案例改善，另一些退化，因此不能将此消融直接替换默认模型。
