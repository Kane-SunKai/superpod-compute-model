# BW1100：来源1与2的改进及72组最终验证

日期：2026-10-28。来源3保持不变：MAC=1，72 CU，每CU四个16×16阵列，1.35 GHz；`backends.py`及`bw1100.json`未修改。

## 结论

12组校准、60组独立验证，全部数值抽样检查通过。≤15%通过数从12/60提高到35/60；中位绝对误差从47.73%降到8.64%，平均绝对误差为25.18%，最大81.52%。**任意尺寸≤15%的目标没有达成。**

## 1. 计时及固定开销

真实实验调用torch.mm(A,B,out=C)，FP16输入/输出、禁用简化精度模式。大算子Graph中64次，小算子256次；预热后测两轮，每轮25次Graph。每次设备事件时间除以Graph中的GEMM数，最后取两轮p50平均。普通eager事件时间另列，不拿主机提交间隙拟合设备计算。只保留p10/p50/p90等汇总及正确性抽样，无逐次样本、Profiler轨迹。

`device_service_s = max(0, median(T_graph - T_model_raw))`，只对12组预先指定的校准尺寸计算。本次得到 **3.105275 µs**；没有利用60组验证尺寸的误差反向调参。它是当前库/执行协议的设备服务补偿，不是任意GPU和任意kernel共享的物理启动常数。默认Policy仍为0；显式加载`examples/bw1100_graph_calibrated.json`才使用本次值。硬件SHA256不匹配会拒绝复用。

Graph反复使用同一地址。验证配置`initial_cache_state=warm-if-fit`：仅当全部A/B加保守工作窗口能放入L2时，假定A/B已驻留；否则仍从冷输入及波间容量受限复用计划估算。真实缓存替换未知，此设置不保证与实际命中率一致。最终C仍计写出，因此并未将热数据的所有HBM服务都强制清零。

## 2. C输出与容量

每Core完整FP32 C驻留寄存器到K结束，寄存器容量规则没有放宽。Shared输入和输出阶段先后执行，检查两者最大占用。输出仅预留有限片数，不要求整块C同时在Shared/L2。

`S_input = input_buffers × (bm+bn) × bk × 2 byte`

`S_output = min(bm×bn×2, output_buffers×output_chunk_bytes)`

`S_shared = max(S_input,S_output)`

`S_register = bm×bn×4 + register_reserve`

`S_L2_work = l2_buffers×(gm×bm+gn×bn)×bk×2 + gm×gn×S_output`

输出流水每片先经L2服务，再经HBM服务；两个不同片可使用独立链路重叠。模型保守地在片抵达HBM时才释放输出槽，确保有界暂存。若设shared-port，输出两段串行。转换/布局成本保留独立配置，不凭空估计；默认仍未校准。

Mapper除输入分块和两级缓冲外，新增4/16 KiB输出片和1/2输出槽搜索。256×384的FP16输出192 KiB，用两片16 KiB暂存只占32 KiB；相应FP32累加384 KiB及预留仍必须放进寄存器预算。聚合容量合法不等于编译器实际线程布局一定可实现。

## 3. HBM输入复用与变长服务

试三种遍历方案：不跨波保留、沿N处理后续输出波保留A条带、沿M处理后续输出波保留B条带。扣除输入/输出工作窗口后，将余量用于保留若干完整K面板。若容量不足以保存完整条带，仅保留K前缀。后续输出波在前缀只搬另一输入，后缀仍搬A+B。尾面板按真实K大小算字节、按阵列粒度补齐计算。

HBM减少不代表L2→Core减少；后者仍按每Core所需的A/B复制数量计费。`pipeline_segments`在这些不同字节大小的段之间保留端口忙闲时间和缓冲释放状态，不在命中/未命中边界重置流水。与显式DAG对照验证。

这是容量受限的理想驻留策略，不是对真实L2替换策略的模拟；不宣称GPU库必然采用此遍历顺序。输出波仍顺序执行，未引入未经容量验证的跨波计算重叠。

## 4. 来源3被冻结时，已有反例证明15%无法全部通过

当前硬件峰值为 `72×4×16×16×1×2×1.35e9 = 199.0656 TFLOP/s`。

对于GEMM，`T_compute_lower_bound = 2MNK / peak`，此下界已经忽略所有搬运、等待和启动。以下8组仍超出实测15%，因此不能靠增加固定启动项或减少搬运来纠正。

## 5. 复现

在项目根目录激活Python（本地无需GPU），运行：

```powershell
python -B -m superpod_compute gemm --m 3072 --n 2304 --k 1024 --hardware superpod_compute/data/bw1100.json --policy examples/bw1100_graph_calibrated.json --no-cache
python -B -m unittest discover -s tests
```

`evaluate --mapping`兼容7个原始整数，也接受9个：`bm,bn,bk,gm,gn,L2槽,Shared输入槽,输出片字节,输出槽数`。如`256,384,16,8,9,2,2,16384,2`。模型与搜索版本已更新，旧缓存不会混用。

验证脚本位于`tools/validation_20261028`；服务器运行目录`/root/sk/compute_validation_20261028`，容器`/workspace`绑定该授权父目录。脚本为每个进程设置日志禁用及缓存路径，未修改驱动/时钟/系统配置。

结果：`results/validation_20261028/final_measurements.json`、`comparison_v1.json/csv`、`comparison_v2.json/csv`；Git备份保留这些小型最终汇总，不保存全部执行过程。
