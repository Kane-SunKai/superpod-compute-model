# BW1100 V3.2：输出写Shared、L2读写分离与算力对照

日期：2026-10-29。默认继续使用MMAC。本文记录实现和测量依据，不把模型中的输出组织等同于rocBLAS实际kernel。

## 1. 本次修改

1. 输出阶段新增W：累加寄存器中的C转换为FP16后，分片写本CU Shared。转换额外耗时维持0，明确不单独计算Shared输出读回临时寄存器的耗时。
2. L2读取使用3768 Byte/cycle，写入使用2990 Byte/cycle；1.30 GHz下分别为4.8984 TB/s与3.887 TB/s。来源是用户硬件表，不是本次L2测量。
3. 新增`mac-throughput`计算后端：16×16个cell、每cell每cycle一次MAC，即每个矩阵单元256 MAC/cycle；4单元/CU、72CU，1.30GHz下为191.6928 TFLOP/s。保留相同的16×16片段划分、尾部补齐、引擎分工和A/B操作数流量，只改变矩阵服务时间。
4. 默认MMAC仍采用独立微基准支持的8周期持续服务间隔，整卡383.3856 TFLOP/s。MAC对照不叠加旧阵列后端的wavefront、LUT或0.98/0.99利用率分支，避免引入第二个变化因素。

## 2. Shared写带宽依据

之前64 Byte/cycle/CU来自Shared读取；原`lds_probe.cpp`计时区间读取`tile[...]`，写初始化在计时之前。这次补测的是写入。

`lds_write_probe.cpp`创建16 KiB Shared数组，在寄存器中产生16字节向量，循环执行volatile Shared写入。共18种配置（1/72/288 blocks ×1/4/8 waves ×4096/16384轮），每种预热8次、计时9次，进行了两轮独立实验。时钟计时在Shared初始化之后开始、在写完成同步之后结束；结果回读校验在计时区间外。结果全部正确。

对每种并发配置，用两个长度的差分计算：

```
写服务率 [Byte/cycle/block]
  = (16384−4096) × threads/block ×16 Byte
    / (长循环block_ticks − 短循环block_ticks)
```

选择72 blocks、每block 8 waves作为每CU一组工作的服务口径，两个实测值为59.247300和59.456707 Byte/cycle/CU，取均值 **59.35200341023225**。该均值来自独立硬件服务测量，不来自GEMM误差拟合；1.30GHz下为77.157604 GB/s/CU。

汇编含`src_shared_base`、展开的`flat_store_dwordx4`，group segment为16384字节，private segment为0。这里的flat地址指向Shared，不能把指令名称中的flat误解成HBM写。测的是对齐16字节volatile写入的有效服务，不宣称覆盖所有bank冲突、并发度或实际GEMM epilogue。

两轮已知`/var/log/hylog`日志文件的大小/mtime核对未变化。服务器新增文件和编译产物只放在`/root/sk/compute_mmac_20261028`对应挂载中；未更改系统日志配置或驱动。

## 3. 每一条搬运路径怎样计费

设所有时间单位为秒，字节单位为Byte；BW为Byte/s。

| 活动 | 服务时间 | 说明 |
|---|---|---|
| H：HBM→L2输入填充 | max(输入Byte/HBM BW, 输入Byte/L2写BW) + 启用的延时 | 采用流式通路的慢端服务率；同一批字节不机械重复相加 |
| R：L2→各CU Shared | 全卡分发Byte/L2读BW + 配置延时 | 共享输入在不同CU的副本分别计入 |
| S：Shared→A/B寄存器 | 最忙CU操作数Byte/每CU Shared读BW | 输入侧64 Byte/cycle保留 |
| W：C寄存器→Shared输出槽 | 本轮最多输出的CU的Byte/每CU Shared写BW | 各CU各有Shared，不把72CU总Byte除以单CU带宽 |
| L：C输出→L2 | 全卡本轮输出Byte/L2写BW + 配置延时 | Shared输出读回不另外计时 |
| D：L2→HBM | max(全卡本轮输出Byte/L2读BW, 全卡本轮输出Byte/HBM BW) + 启用的延时 | L2读与HBM写作为流式通路 |

上述读写方向独立服务不等于已验证任意混合读写都能满速并行。当前独立端口假设保留；`shared-port`模式将L和D串行，W为独立Shared写资源。输入侧LDS写服务仍包含在原L2→Shared搬运抽象中，没有另加一条输入写阶段。

## 4. 输出缓冲与等待

```
全K累加完成
   → W_i：FP16小片写入Shared槽 i%2
   → L_i：小片进入L2窗口 i%2
   → D_i：小片从L2写回HBM
```

Shared槽从W开始到L完成占用，L2窗口从L开始到D完成占用。下一个复用同槽的事件必须等旧数据消费完成。不同资源的活动可以重叠，等待由依赖推出来；不是将W、L、D的总服务量简单相加。

每CU 256×384的C为384 KiB FP32累加结果，输出为192 KiB FP16。4 KiB一片，共48片；2个Shared输出槽共8 KiB。4/16 KiB仍是枚举候选，既非硬件强制粒度，也非实测最优粒度。更换粒度后服务、缓冲与等待重新计算。

## 5. 同口径算力对照结果

沿用原72组Graph实测，不重新运行整组GEMM。12组历史校准形状单列，60组验证形状统计≤15%通过率。规则组沿用原定义：包含decode的M=1，非规则组就是预先定义的10组irregular。两个后端各自完整搜索相同候选空间，不只评估同一固定分块。

固定设备服务 **3.121244690369221 µs** 在两方案中保持相同，未重新拟合。策略硬件指纹显式更新，代表同一固定服务迁移到受控对照，不代表重新做了启动校准。

| 方案 | 规则组通过 | 规则组平均绝对误差 | 非规则组通过 | 全60组通过 |
|---|---:|---:|---:|---:|
| MMAC，8 cycles/16×16×16 | 41/50（82%） | 7.505% | 0/10 | 41/60 |
| 256 MAC/cycle/矩阵单元 | 34/50（68%） | 19.156% | 0/10 | 34/60 |

默认保留MMAC，因为规则组通过率更高。MMAC旧V3.1也是41/50，本次是补全服务路径，没有宣称补完后通过率必然上升。256 MAC/cycle的吞吐约为MMAC的一半，在较大计算密集型矩阵上常明显高估时间；小矩阵和带宽受限decode差别较小。

256 MAC/cycle下，60组中有9组仅按纯计算峰值下界就比实测慢15%以上；MMAC为0组。这不是靠输出带宽调整能够消除的差异。

固定示例3072×1024乘1024×2304，映射256,384,16,12,6,1,2,4096,2,2：

- MMAC总时间：50.182891 µs。
- 输入/计算64面板：38.702586 µs。
- 输出48片：8.359060 µs。
- 256 MAC/cycle同映射：87.992121 µs。
- 相同形状Graph实测：64.708743 µs。MMAC这一例仍未达到15%，不把它包装成精度达标示例。

## 6. 文件与复现

- `superpod_compute/data/bw1100.json`：默认MMAC及新增方向带宽。
- `superpod_compute/data/bw1100_mac256.json`：256 MAC/cycle对照。
- `examples/bw1100_graph_calibrated.json`、`examples/bw1100_mac256_comparison.json`：同固定服务、分别匹配硬件指纹。
- `tools/compare_compute_modes.py`：两后端重新搜索；报告记录源代码、硬件、策略与实测文件SHA256。
- `tools/verify_v32.py`：快速重算144条记录中的映射，核对安装后的代码输出。
- `tools/bw1100_service_probe/lds_write_round1.json`、`lds_write_round2.json`：原始18组×2硬件微基准结果。
- `results/validation_20261029_v32/comparison_modes.json`与CSV：144条预测、映射、误差和汇总。
- `tools/docs_walkthrough/refresh_data.py`：用代码重生成HTML算例数据；`build.py`重生成HTML和User Guide。

主流程代码在`operators.py`，输出调度在`scheduler.py::output_pipeline`，两种矩阵服务在`backends.py`。新增字段默认兼容旧配置：L2方向字段为0时回退统一带宽，Shared写字段为0时不计这项服务。模型/搜索版本均已更新，旧缓存不会误用。

60项单元测试通过，包括输出逐事件DAG对照、槽生命周期、分段加速与尾片、MAC与MMAC只改变计算服务的检查。HTML有新的W行、Shared/L2缓冲存活区间和精确输出时间图；原矩阵分块选择与复用开关保留。
